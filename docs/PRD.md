# 人類使用說明書 — 第一版產品規格
版本：1.0.0｜決策日期：2026-09-07｜狀態：測驗、保存與分享已實作；各環境驗收狀態見 IMPLEMENTATION-PLAN.md。

## 產品目標
做一個能真的玩完、想分享給朋友的輕量生活娛樂產品，而不是只有首頁的展示殼。
第一版驗證的是「題目願意答、結果想保存、朋友打得開」，不保證流量、病毒傳播或人格判讀準確。
主要使用者為繁體中文的一般網友；優先處理手機瀏覽器、從通訊軟體點開連結的情境。

## 名稱與文字
產品名稱：人類使用說明書。
主標語：出廠時沒附的那本，現在補給你。
輔助文字：8 個日常選擇，翻開你的使用說明書。
主按鈕：開始翻開我的說明書。
不使用假用戶數、測驗準確率、抽獎、付費牆或倒數逼迫。
規劃答題體驗約 2 分鐘，這是產品設計目標，不是已量測的平均。

## 第一版只有三個產品模組
### 1. 開始與作答
首頁直接說清楚玩法、8 題、娛樂性質與免登入。
有未完成進度時明確提供「繼續上次測驗」及「重新開始」。重新開始要確認是否清除進度。
單題單頁、每題 3 個答案，用 native radio group；點選後不自動跳頁，按「下一題」繼續。
顯示「第 3 / 8 題」與有文字標籤的進度；未選答案不能進下一題。
允許返回上一題，先前選項保留；改答案後從完整答案集重新算分，不能疊加舊分。
切題後把焦點移到題目標題，轉場尊重 prefers-reduced-motion。
儲存 quizVersion、目前題號、已選 option ID；讀取時檢查版本、型別、長度、ID 所屬題目。
資料損壞、舊版本或儲存被阻擋時顯示簡短提示，仍允許重新開始／當次完成，不得白屏。

### 2. 結果與圖片分享
6 種角色使用 core/quiz.v1.json 的固定完整文案。
結果頁提供角色名、型號、代表句、啟動方式、低電量訊號、相處須知、注意事項、隱藏技能。
頁尾保留娛樂性測驗聲明，不出示科學準確率、虛構人群比例、病理標籤或優劣排名。
計分在瀏覽器執行，依 core/score.mjs 的確定性規則；同版本同答案同結果。
不要把內部分數包裝成心理量表；第一版不顯示百分比或人格雷達圖。
分享按鈕須真的有作用：原生分享（可用時）、複製連結、儲存 PNG；取消分享正常返回。
PNG 建議 1080×1350，放角色名、代表句、3 個精簡說明、品牌與娛樂聲明，不必塞進全部長文。
圖片只用原創或合法可用素材。圖片產生失敗可重試，功能不可只彈「成功」卻沒有產物。
分享 URL 只放 quizVersion 與 resultId；不放完整答案、裝置識別、姓名、私人資料。
朋友打開的是「被分享的角色介紹」；不是朋友本人已完成測驗，也不能讓模板覆蓋朋友自己的作答進度。
從分享結果可點「換我測測看」開始。未知角色或版本顯示可理解的回復入口。
社群連結預覽第一版只承諾共用品牌圖；每種角色專屬 OG 預覽需另做預渲染公開頁，留待後續。

### 3. 關於、展示與發布準備
關於頁說明產品目的、娛樂性質、資料只在此瀏覽器處理及清除資料入口。
不要宣稱整個託管服務零紀錄；應區分應用程式沒有上傳答案與託管商自己的訪問紀錄。
網站 footer 預留 GitHub 原始碼入口，但只有真實 remote URL 已設定後才顯示，不提供假連結。
README 須有實際完成的功能、截圖、架構與計分取捨、測試方式、已知限制。
第一版不加入對外追蹤服務。若後續要蒐集完成率、分享率，需另定匿名事件與隱私說明。

## 前端結構建議
React 19 + TypeScript + Vite；使用者於 2026-09-07 調整原始 Vue 選型，以 React 的元件、hooks 與純函式分層實作。套件版本與相容性紀錄見 IMPLEMENTATION-PLAN.md。
React Router 使用 HashRouter；路由範例為 /、/quiz、/result/v1/:resultId、/about。
URL 中 v1 固定對應題庫版本 1.0.0；未來修改題庫或權重時新增版本路徑，不覆寫舊結果的含義。
components 分出 QuizProgress、AnswerOption、ManualCard、ShareActions；views 分出首頁、作答、結果與關於。
state/useQuiz 管理作答；domain/score 純函式；data/quiz.v1 保留版本化資料；services/exportCard 與分享／storage 分開。
不強制加入全域狀態庫；小型第一版採 hook 即可。
所有外部輸入驗證；一般 React 文字插值，不以 dangerouslySetInnerHTML 渲染 URL 或使用者內容。

## 視覺方向（給設計／實作階段的 brief，尚非已完成設計稿）
以「真的像一本有個性的使用手冊」為概念：奶油白紙感、墨色文字、單一暖橘重點。
採編輯式留白、大字標題、手冊型號與少量原創角色插畫，不做企業後台、制式聊天 UI 或一排空泛功能卡。
手機單欄、清楚觸控選項；桌機用留白與手冊封面形成焦點，不任意拉寬題目文字。
同一角色的網站結果卡與 PNG 使用相同字級階層和視覺語言；字體優先系統字體，降低外部依賴。
畫面至少包含：完整首頁、選項選中狀態、結果、分享失敗／成功狀態、375px 手機版。
正式實作前按開發環境的設計技能生成／確認視覺，文字與控制項必須是原生 HTML，不把整頁設計稿當 UI。

## 計分規則
每個選項給主類型 3 分、副類型 1 分。完成 8 題時總分固定 32。
以最高總分決定結果；平手從最後一題往第一題比較該題權重，直到分出唯一類型。
不使用 random，不以宣告順序偏袒某個類型。所有 6,561 種答案組合都應能計算，6 種結果都要可到達。
這是遊戲內容規則，不是心理學模型；可達性測試不能當作科學效度或使用者分布。

## 現在／之後／可忽略
現在：自己做測驗、看完整說明書、儲存 PNG、分享連結、手機可用。
之後：朋友眼中的我，需另外設計邀請、身份／暱稱、資料保存期限、反濫用與刪除機制。
可忽略：AI 即時生成、付費、會員、匿名留言、排行榜、自架伺服器、廣告、推播。

## 三階段完成標準
1. 基礎：視覺方向與畫面規格確認，首頁／作答／結果架構成立，不捏造可點擊的假功能。
2. 功能：能完整做完一次測驗、回頭修改、重新整理恢復、產生圖片、分享給另一個瀏覽器。
3. 展示：型別／單元／瀏覽器測試、手機視覺驗收通過，README 與發布設定備妥；經授權才實際公開。
